# ADR-0065: OPDS 2.0

- **Status:** Accepted
- **Date:** 2026-11-11
- **Depends on:** [ADR-0006](0006-catalog-api-and-opds.md),
  [ADR-0064](0064-opds-feeds-list-newest-first.md)
- **Amends:** ADR-0006, which deferred OPDS 2.0

## Context

The catalog spoke OPDS 1.2 only. JSON clients such as Readest, Thorium and
the KOReader OPDS Plus plugin prefer OPDS 2.0 (`application/opds+json`),
and the 1.2 feeds carry compromises made for KOReader's built-in sync
(ADR-0064): folders, shelves and browse pages live in facet links because
a navigation entry in an acquisition feed crashes it. The 1.2 entries also
drop what Atom has no good place for, such as a book's position in its
series and its subjects, and an audiobook linked to a book was invisible.

## Decision

The server serves OPDS 2.0 under `/opds/v2`, beside `/opds/v1.2`, from the
same loaders and behind the same chain: secure transport, the OPDS rate
limit, HTTP Basic with a token secret, and `library-read`.

| Route | Content |
|---|---|
| `GET /opds/v2` | `navigation` to folders, the four shelves and series, contributors and tags; a "Newest" group with the first page of books |
| `GET /opds/v2/new` | every granted book newest first, with the 1.2 root's keyset cursor in `next` |
| `GET /opds/v2/folders/{folder}` | the folder newest first, and a templated `search` link `…/search{?query}` |
| `GET /opds/v2/folders/{folder}/search?query=` | one unpaged page of results |
| `GET /opds/v2/shelves/{shelf}` | the caller's shelves from ADR-0064 |
| `GET /opds/v2/entities/{kind}` and `{kind}/{entity}` | browse navigation with `numberOfItems`, then the books |
| `GET`/`HEAD /opds/v2/books/{id}/download`, `/cover`, `/audiobook` | bytes |

A publication carries `@type` `http://schema.org/Book`, an identifier
(the book's ISBN or UUID when it parses as one, else
`urn:liseur:book:{id}`), title, subtitle, language, publisher, dates, a
bounded description, contributors by role with links to their feeds,
tags as `subject`, and `belongsTo.series` with the position. Its links
are the EPUB acquisition and, when the reader can play it, the linked
`.m4b` as a second acquisition of type `audio/mp4`. The audiobook follows
the native audio route's rule: an active alignment whose digests still
hold, and a grant on both the book's and the audiobook's folders. Images
list the thumbnail first and the full cover second.

A 401 under `/opds/v2` keeps the `WWW-Authenticate: Basic` header that
Basic-only clients prompt on, and its body is an Authentication for
OPDS document (`application/opds-authentication+json`) describing Basic
authentication with token labels. There is no separate route for the
document, so no new open route exists.

Each 1.2 feed gains one `alternate` link of type `application/opds+json`
to its 2.0 twin. A later page of the 1.2 root maps to `/opds/v2/new` at the
same cursor.

An empty page still writes its collection as `[]`. The OPDS 2.0 schema
asks for at least one item, which an empty page cannot have, and clients
treat a missing collection as a malformed feed. The root drops its
"Newest" group when the library has no books.

## Not in this decision

Readium progression sync over OPDS would put reading state on a catalog
credential, which ADR-0006 rules out; it needs its own decision. Readium
Web Publication manifests for streaming and OPDS-PSE are also left for
later.

## Consequences

KOReader's built-in catalog keeps using `/opds/v1.2`. A client that syncs
by walking `next` from the configured URL, OPDS Plus included, should be
given `/opds/v2/new`, because the 2.0 root is navigation and its group is
one page.

Shelves expose the token owner's own reading state, as in 1.2. Nothing
about storage changes and no migration runs.
